# BKID Workflowboost 2.5.0 설치

1. Rhino를 모두 종료합니다.
2. `BKID_AutoCrop_Setup_2.5.0.exe` 실행 → **설치 / 다시 설치**
3. 기존 설치가 있으면 **“설치되어 있습니다. 삭제하고 다시 설치할까요?”**가 표시됩니다. **예**일 때만 삭제·재설치를 진행합니다. **아니요**면 기존 설치를 유지합니다.
4. 처음 설치하거나 예를 선택했다면 Rhino Installer에서 **현재 사용자 설치**를 완료합니다.

## 좌클릭 / 우클릭

좌클릭은 기존 1배 캡처를 바로 실행합니다. 우클릭은 **×2·×3·×4** 선택 창을 표시합니다. 예를 들어 뷰포트가 1200×800px이면 ×2는 2400×1600px로 캡처한 뒤 자동 크롭합니다. 화면에 표시하는 크기는 크롭 전 캡처 해상도입니다. 원본 이미지를 단순 확대 저장하는 방식이 아닙니다.

선택 즉시 캡처하고 선택 창을 닫습니다. 취소·Esc·창 닫기는 캡처하지 않습니다. 배율을 영구 설정으로 저장하지 않아 다음 좌클릭은 그대로 1배입니다. 사방 1px 투명 여백은 유지됩니다. 우클릭 창은 `BKIDAutoCropResolution`으로도 열 수 있습니다.

## PNG 저장 폴더 (2.5.0)

툴바 **우클릭 → 저장 폴더 변경…**에서 폴더를 선택하세요. 현재 경로가 선택창에 표시됩니다. 폴더 선택을 완료하면 이후 모든 배율의 캡처에 적용하고 Rhino 사용자 설정에 저장해 재시작 후에도 유지합니다. 폴더 선택을 취소하면 기존 경로를 유지합니다.

폴더만 바꾸고 캡처하지 않으려면 배율을 고르지 않고 해상도 창을 닫으세요. `BKIDAutoCropFolder` 명령도 폴더 선택만 수행합니다. 초기 기본 위치는 바탕화면 `BKID_Captures`입니다. 기존 PNG는 그대로 두고 새 캡처부터 선택한 폴더에 저장합니다. 선택 폴더에 쓰기 오류가 있으면 F2 기록에 오류를 표시하며 다른 위치로 바꿔 저장하지 않습니다.

## 백업 없는 교체 설치

기존 버전이 있고 재설치에 동의한 경우 RHP/RUI와 관련 등록 정보를 제거한 뒤 새 버전을 설치합니다. **백업과 자동 복원은 없습니다. 설치를 취소하거나 새 설치가 실패하면 이전 버전이 없는 상태가 될 수 있습니다.** 이 내용은 설치 시작 화면과 실패 안내에도 표시합니다. 기존에 만들어진 과거 백업 폴더는 추가로 삭제하지 않습니다.

삭제 범위는 현재 사용자 Rhino 6/8 표준 `Plug-ins` 폴더에서 파일명과 플러그인 GUID가 일치하는 BKID RHP 및 같은 이름의 RUI, 해당 GUID의 현재 사용자 등록 정보입니다. 이전 1.x BKID AppData 설치의 알려진 스크립트/RUI/로고와 2.0~2.5 추출 스크립트도 정리합니다.

다른 플러그인, 모델, PNG 캡처, 다운로드한 사용자 소스 폴더는 삭제하지 않습니다. 모든 사용자용(HKLM) 설치는 자동 제거하지 않고 안내합니다. 파일 링크·정션과 읽기 전용 대상은 삭제 전 점검에서 거부합니다. 삭제 및 등록 정보 변경이 일부 진행된 후 오류가 발생하면 복원하지 않으며 다시 설치가 필요합니다.

Rhino Installer의 종료 코드보다 실제 설치 결과를 우선 확인합니다. 새 RHP가 배포 파일과 일치하고 해당 RUI의 식별자·필수 명령이 확인되면 **403 반환 후에도 설치 완료**로 처리합니다. 반대로 0을 반환해도 새 파일이 없거나 이전 버전이면 완료로 표시하지 않습니다. Rhino가 저장한 도킹 위치·XML 형식 변경은 실패로 간주하지 않습니다. RHI 파일을 직접 실행하면 위의 사전 삭제 작업은 실행되지 않습니다.

## 툴바 표시

- 이 사용자 설정에서 처음 성공적으로 툴바를 열었을 때 초기화 완료를 저장합니다.
- 이후 Rhino 실행 시 플러그인은 툴바를 강제로 열거나 `Visible=true`로 변경하지 않습니다. 사용자가 도킹하거나 숨긴 상태는 Rhino가 관리합니다.
- 툴바를 다시 열려면 `BKIDAutoCrop`을 입력합니다. 캡처 직접 명령은 `BKIDAutoCropCapture`입니다.
- 최초 표시가 실패하면 초기화 완료로 기록하지 않아 다음 실행에서 재시도할 수 있습니다.

설치 마법사는 제공된 원본 이미지를 여백 없이 왼쪽에 표시합니다. Rhino 툴바의 버튼은 기존 AutoCrop 로고를 사용합니다.

## 검증

실제 RHP/설치 EXE 빌드, 내장 RHI/원본 이미지 일치, RUI 참조, 백업 없는 삭제·반복 삭제·다른 파일 보존·한글 경로·링크/읽기 전용 사전 거부를 검사합니다. Windows Installer 및 등록 정보 처리, 실제 Rhino 6/8 첫 표시·도킹·숨김 상태 재시작 유지와 캡처는 **미실행**입니다. 이전 보안 프로그램 위협 탐지 원인도 아직 확인되지 않았습니다.

## 저장된 우클릭 연결 갱신

2.4.2 첫 실행 시 기존 AutoCrop 버튼의 우클릭이 캡처 명령에 연결돼 있으면 해상도 선택 명령으로 수정하고 툴바를 다시 읽습니다. 다른 툴바에 복사한 버튼도 캡처 명령으로 식별합니다. 도킹·표시 상태를 저장해 다시 적용하며, 매번 시작할 때 재갱신하지는 않습니다. 여전히 우클릭이 바로 저장되면 `BKIDAutoCropRefresh`를 입력하세요. 선택 창 자체를 직접 여는 명령은 `BKIDAutoCropResolution`입니다. 오류가 있으면 F2 명령 기록에 표시됩니다.

## Rhino 6 점검 및 버튼 설명 (2.4)

- 플러그인 기준 SDK를 RhinoCommon 6.35에서 초기 정식 6.0.18016.23451로 낮추고, 툴바는 RUI 2.0으로 생성합니다. 초기 6.0 SDK를 대상으로 C# 플러그인과 Python이 호출하는 Rhino 캡처·선택 API를 강한 형식으로 컴파일 검사합니다.
- 시작 준비 확인은 Eto 창 대신 Rhino 네이티브 창 핸들을 사용합니다. 저장된 툴바 갱신에 오류가 생겨도 첫 툴바 표시를 막지 않도록 분리했습니다.
- 왼쪽 마우스 설명: **기본 해상도(1배)로 자동 크롭·PNG 저장**
- 오른쪽 마우스 설명: **해상도 선택 (×2·×3·×4)**

Rhino 6/8 실제 실행은 이 Linux 환경에서 확인하지 못했습니다. 따라서 Rhino 6 실행 실패가 해결되었다고 확정할 수 없습니다. 실패 시 F2 명령 기록과 Rhino 6 서비스 릴리스 번호가 필요합니다. `BKIDAutoCrop`은 툴바 표시, `BKIDAutoCropCapture`는 기본 캡처, `BKIDAutoCropResolution`은 해상도 선택 명령입니다.

2.4.2에서는 공통 설명이 남아 있는 이전 버튼을 새 좌우 설명으로 연결하고 툴바를 한 번 다시 읽습니다. 기능 명령과 도킹 그룹은 유지하며, 새 설명용 매크로 식별자를 사용해 기존 캐시를 재사용하지 않도록 했습니다.

## 최초 실행의 중복 툴바 방지 (2.4.2)

Rhino가 자동으로 로드한 툴바의 경로가 설치 폴더와 달라도 같은 파일/그룹 ID로 인식해 재사용합니다. 이미 표시된 그룹에는 다시 표시 요청을 하지 않습니다. 최초 실행의 올바른 RUI는 닫았다 다시 열지 않고, UI 열기 중 발생하는 중첩 Idle 호출도 무시합니다.

기존에 로드된 중복 전용 컬렉션은 저장 후 정리하고, 공유 컬렉션에서는 해당 플러그인의 중복 그룹만 숨깁니다. 도킹된 항목을 우선 유지합니다. 사용자가 숨기거나 닫아 둔 정상 툴바를 시작 시 강제로 다시 열지 않습니다. 실제 Rhino UI 재현 검증은 별도로 필요합니다.
