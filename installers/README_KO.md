# BKID AutoCrop 2.1 — 실제 툴바와 교체 설치

## 설치 방법

1. `BKID_AutoCrop_Setup_2.1.0.exe`를 다운로드합니다. 저장소 ZIP을 받았다면 압축을 푼 뒤 `installers` 폴더에서 찾을 수 있습니다.
2. 열려 있는 Rhino를 모두 종료합니다. 설치 프로그램은 Rhino를 강제로 종료하지 않습니다.
3. EXE를 실행하고 **설치 / 다시 설치** 버튼을 누릅니다.
4. 이어서 열리는 Rhino Installer 화면에서 **현재 사용자 설치**를 진행합니다. 이 단계까지 완료해야 설치됩니다.
5. Rhino를 실행하면 **BKID AutoCrop**이라는 작은 툴바 창을 표시하도록 구현했습니다. 안의 로고 버튼이 자동 크롭 기능입니다.

2.0의 별도 버튼 창과 Eto 대체 창은 새 플러그인에서 생성하지 않습니다. Rhino의 실제 RUI 툴바이며 이동·도킹은 Rhino 기본 기능을 사용합니다. 닫았다면 `BKIDAutoCrop`으로 다시 표시합니다. `BKIDAutoCropCapture`는 직접 캡처 명령입니다.

기존 창의 ‘자동 표시’ 체크박스는 없어졌고, 새 버전은 시작 시 툴바를 표시합니다. 새 버전에서는 기존 `ShowOnStartup` 설정을 사용하지 않습니다.

## 기존 설치 정리

권장 EXE 설치 경로에서 수행하는 작업입니다.

- 현재 사용자의 Rhino 6/8 `Plug-ins` 폴더에서 `BKID.AutoCrop.rhp`와 **우리 플러그인 GUID가 일치하는 파일**을 찾습니다. 해당 RHP와 같은 이름의 RUI를 백업하고 설치 위치에서 제거합니다. 관련 현재 사용자 등록 정보도 백업 후 제거합니다.
- 1.x가 만들었던 `%APPDATA%/BKID/AutoCrop/Rhino6`·`Rhino8`의 알려진 스크립트·RUI·로고 파일과 2.0의 추출 스크립트를 백업 후 제거합니다.
- 새 RHI 패키지를 Rhino Installer로 설치합니다. 새 RHP와 RUI가 배포 파일과 정확히 일치하는지 확인해야 완료로 처리합니다. 종료 코드가 0이라는 이유만으로 성공 처리하지 않습니다.
- 새 플러그인 첫 로드 시, 이전 BKID 스크립트를 가리키는 `RunAutoCrop`·`ShowAutoCrop` 별칭과 이전 경로의 열린 툴바를 정리합니다. 사용자가 다른 매크로로 변경한 같은 이름의 별칭은 지우지 않습니다.

백업 위치는 `%LOCALAPPDATA%/BKID/AutoCrop/InstallBackups/날짜_ID`입니다. 원래 파일 경로는 `files.txt`, 등록 정보는 `.reg` 파일로 보관합니다. 취소·실패하면 이전 파일과 등록 정보 복원을 시도합니다. 복원 위치에 다른 새 파일이 생겼으면 덮어쓰지 않고 백업 경로를 표시합니다.

기존 PNG 캡처, Rhino 모델, 다른 플러그인, 사용자 소스 폴더는 삭제하지 않습니다. 파일 링크·정션을 통한 정리는 거부합니다. 모든 사용자용(HKLM) 설치가 있으면 자동 제거하지 않고 안내합니다. 그 경우 기존 모든 사용자용 설치를 먼저 제거해야 합니다. 이 EXE의 자동 정리 범위는 현재 사용자 표준 설치입니다.

`BKID_AutoCrop_2.1.0.rhi`는 기본 패키지입니다. 이를 직접 실행하면 위의 사전 제거·백업 검사는 실행되지 않으므로, 요청하신 제거 후 재설치에는 **EXE**를 사용하세요.

## 검증 상태

- 정식 RHP와 Windows 설치 EXE Release 빌드 성공, 오류·경고 없음.
- 어셈블리 버전·GUID, 캡처 스크립트·로고 내장, 설치 EXE의 내장 RHI 일치 확인.
- RHI에 같은 이름의 `BKID.AutoCrop.rhp`·`BKID.AutoCrop.rui`가 들어가는지와 XML/아이콘 참조·PNG 투명도 확인.
- 실제 설치기에 쓰는 파일 처리 코드를 .NET 테스트에서 실행: 백업 검증 후 제거, 취소 복원, 반복 복원, 한글 경로, 새 파일 덮어쓰기 거부, 링크 거부, 다른 파일 보존.
- **Windows 실기 미실행**: EXE 실행, Rhino Installer 연동, 등록 정보 제거·복원, Rhino 6/8 툴바 생성·재시작 유지·도킹·버튼 캡처. Linux 빌드·파일 테스트가 이 동작을 보증하지 않습니다.

실기 확인 순서: Rhino 종료 → 기존 2.0 위에 EXE 설치 → Rhino 실행 → 별도 버튼 창이 아닌 툴바 표시 → 로고 버튼 캡처 → 도킹 → 재시작 → 툴바/위치 확인 → 다시 EXE 실행 → 중복 툴바 여부 확인.

오류는 F2 기록의 `BKID AutoCrop toolbar startup:` 또는 설치 프로그램 오류 창과 백업 경로를 확인하세요.
